# От lab-находки — к заботе о своём сайте (без скана продакшена)

Правило: прод не сканируем ничем. Каждую строку ниже проверяем **руками из админки/панели хостинга**, не запросами к сайту.

| Класс из lab-отчёта | Что сделать на своём сайте |
|---|---|
| Устаревшее ПО / CVE | Админка CMS → версии ядра, темы, плагинов; версия PHP/MySQL в панели хостинга. Обновить по очереди, сначала бэкап |
| Слабый/дефолтный вход | Уникальный длинный пароль админа, 2FA, нестандартный URL админки, отдельная учётка редактора вместо общего admin |
| Обход авторизации | Матрица прав: кто что видит; отключить лишние учётки; проверить, что закрытые разделы отдают 403 без входа (вручную в браузере) |
| SQL-инъекция (класс) | Только официальные плагины/темы из каталога CMS, обновления; формы — штатные компоненты, не самописные |
| XSS (класс) | Не вставлять чужой JS/виджеты без проверки; комменты/формы с капчей и модерацией |
| HTTP-заголовки | В панели хостинга или `.htaccess`/конфиге: HSTS, X-Frame-Options / frame-ancestors, Referrer-Policy; CSP — аккуратно, после теста |
| TLS/сертификат | Панель хостинга → автопродление Let's Encrypt, редирект http→https, протокол не ниже TLS 1.2 |
| Открытые порты (nmap-класс) | Панель/VPS: закрыть всё кроме 80/443 (+ SSH только по ключу и, желательно, с allowlist IP) |
| Бэкапы и восстановление | Автобэкап файлов+БД ежедневно, копия вне хостинга; раз в месяц — пробное восстановление |

## Что привезти сюда для разбора

- JSON-отчёт Lab Coach из домашней VM (`data/reports/scan-N/scan-N.json`) — команда `explain`.
- Текст из админки (версии, список плагинов) — разберём как учитель, что обновить первым.
- Скрин/текст заголовков ответа сайта из devtools браузера.

Скажи, на чём стоит сайт (CMS и хостинг) — сужу чек-лист под твой стек.
