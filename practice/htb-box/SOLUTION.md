# SOLUTION — intended-путь PlanBox (спойлер, открывать после своих попыток)

## Foothold (два сходящихся пути)

1. **Через бэкап.** `robots.txt` запрещает `/backup` → `gobuster` находит
   `/backup/site-backup.zip` → внутри `deploy-notes.txt` с парой для веб-логина →
   `/login.php` → дашборд прямо пишет про reuse пароля в SSH.
2. **Через LFI.** `view.php?page=` без валидации → чтение локальных файлов,
   включая `config.php` с тем же секретом (каким именно способом читать исходник
   PHP — часть упражнения).

Итог: SSH `student@planbox.htb` → `~/user.txt` (`PLANBOX{u53r_fl4g_l4b_0nly}`).

## Privesc (два учебных пути)

1. **sudo.** `sudo -l` показывает `NOPASSWD` на `/usr/bin/find` → смотреть запись
   этой утилиты в GTFOBins и думать, что она умеет помимо поиска.
2. **cron.** `/etc/cron.d/planbox-backup` каждые 2 минуты запускает от root скрипт,
   доступный тебе на запись → подумать, что произойдёт, если его содержимое изменить.

Итог: чтение `/root/root.txt` (`PLANBOX{r00t_fl4g_l4b_0nly}`).

## Разбор полётов (что вынести)

- Запрет в `robots.txt` ≠ защита: это подсказка для перебора.
- Бэкапы с секретами на веб-сервере и reuse паролей — два самых дешёвых провала.
- `sudo NOPASSWD` на «безобидной» утилите и writable cron-скрипты — классика privesc.
