# Программа «Все классы атак + защита» (только легальные полигоны)

Цель: руками проработать каждый класс — понять, как выглядит, и уметь закрывать на своём сайте.
Где работаем: **PlanBox** (`192.168.56.110`), **Metasploitable 2** (host-only),
**PortSwigger Web Security Academy** (бесплатные легальные лабы под каждый класс, нужен только аккаунт),
комнаты **THM/HTB** по темам. Прод и чужие хосты — вне программы всегда.

Шаблон модуля: 🎯 цель → 📖 суть (теория) → 🧪 lab (где крутить) → 🛡 защита своего сайта → 🤖 coach → ✅ самопроверка.
Темп: 1 модуль = 1–2 вечера. Порядок — от простого к сложному, не прыгать.

## Блок A. Фундамент

### A1. Разведка и сканирование
- 📖 Что находят сканеры: порты, версии, веб-пути, известные шаблоны. Шумность и легальность.
- 🧪 `nmap -p-` + `-sC -sV` по PlanBox; `lab-coach scan` туда же; сравнить выводы.
- 🛡 На своём сайте (из панели, не сканом): закрыть лишние порты, убрать версии из баннеров/заголовков, фаервол.
- 🤖 `scan_lab_target` → `explain_report`.
- ✅ Объяснить разницу `-p-` vs `--top-ports` и что означает каждая строка services.txt.

### A2. Аутентификация: слабые креды и перебор (теория атаки)
- 📖 Дефолтные пары, reuse, словари, credential stuffing; lockout и rate limit как ответ.
- 🧪 PlanBox: путь через найденные креды (reuse). Перебор НЕ крутим даже дома — разбираем защиту.
- 🛡 Длинный уникальный пароль админа, 2FA, смена URL админки, лимиты входов, алерты о входах.
- 🤖 `explain` находки «default login».
- ✅ Чек-лист входа своего сайта по MAP-TO-MY-SITE.

### A3. Управление сессиями и JWT
- 📖 Токены, фиксация, угон через XSS, rotation, TTL. Подмен сессий НЕ делаем.
- 🧪 Теория + разбор своих cookie в devtools (флаги HttpOnly/Secure/SameSite).
- 🛡 Выход с инвалидацией, rotation после логина, короткие TTL, 2FA на смену почты/пароля.
- ✅ Найти в своём браузере cookie без флагов и понять, чем это грозит.

## Блок B. Веб-классика (ядро)

### B1. SQL-инъекции (включая blind — только теория)
- 📖 In-band / blind / out-of-band: идея — смешивание кода и данных. Blind отличается лишь каналом ответа, чинится так же.
- 🧪 WSA → SQL injection (все уровни,включая blind — там это легально); дома — только чтение теории.
- 🛡 Prepared statements/ORM, минимальные права у DB-пользователя, скрытие ошибок БД, обновления СУБД.
- 🤖 `explain` находки «SQL Injection».
- ✅ Объяснить, почему экранирование кавычек — не замена prepared statements.

### B2. XSS: reflected / stored / DOM
- 📖 Три типа, контексты (HTML/атрибут/JS/URL), кража сессии как следствие.
- 🧪 WSA → Cross-site scripting (все три типа — легально).
- 🛡 Экранирование по контексту, CSP, `HttpOnly` + `SameSite` на cookie, модерация пользовательского контента.
- ✅ Для каждого типа — одним предложением, где чинить: сервер, хранение или JS.

### B3. CSRF
- 📖 Действие от имени жертвы через её браузер; связка с XSS и SameSite.
- 🧪 WSA → CSRF.
- 🛡 CSRF-токены, `SameSite=Lax/Strict`, проверка Origin/Referer на важных действиях.
- ✅ Объяснить, почему GET-запрос не должен ничего менять.

### B4. SSRF (включая обходы — теория)
- 📖 Сервер ходит по чужому URL: metadata cloud, внутренняя сеть. Обходы фильтров (дешифровки/редиректы) — знать поименно, крутить только в WSA.
- 🧪 WSA → SSRF.
- 🛡 Allowlist назначений, запрет `169.254.169.254`/внутренних диапазонов, egress-фильтр, таймауты.
- ✅ Назвать 3 места, где SSRF прячется: превью ссылок, импорт по URL, вебхуки/интеграции.

## Блок C. Файлы и выполнение кода

### C1. LFI / Path Traversal (+ RFI — теория)
- 📖 `?page=` без валидации → чтение файлов; RFI — тот же класс через URL (часто выключен настройками).
- 🧪 PlanBox `view.php` (чтение своих файлов) + WSA → Path traversal.
- 🛡 Allowlist имён, `basename`/нормализация, файлы вне webroot, запрет `allow_url_include`.
- ✅ Прочитать через LFI два своих файла и объяснить, какой настройкой закрывается каждый.

### C2. Загрузка файлов
- 📖 Исполняемая загрузка, двойные расширения, SVG/Polyglot как носители.
- 🧪 WSA → File upload (легально). Дома загрузчик не пишем — разбираем защиту.
- 🛡 Allowlist типов + перекодирование картинок, случайные имена, хранение вне webroot, `NoExec` на каталоге, CSP.
- ✅ Список из 5 проверок загруженного файла по порядку.

### C3. Command injection / SSTI / XXE / Deserialization (продвинутый уровень)
- 📖 Общее: недоверенный ввод выполняется (shell / шаблонизатор / XML-парсер / распаковщик объектов).
- 🧪 WSA → OS command injection, SSTI, XXE, Deserialization (там — легально). Дома — теория + поиск этих мест в своём коде глазами.
- 🛡 Никогда shell из ввода (API/библиотеки вместо), шаблоны не из ввода, запрет external entities/DTD, JSON вместо сериализованных объектов, обновления.
- 🤖 `explain` любой такой находки из Nuclei.
- ✅ Для каждого класса — одной строкой «где в моём сайте такое может жить».

## Блок D. Логика доступа

### D1. IDOR / Broken Access Control
- 📖 Предсказуемый id + нет проверки владельца. Перебор чужих id НЕ выполняем нигде, кроме легальных лаб.
- 🧪 WSA → Access control (там — легально); PlanBox — разбор своей матрицы прав.
- 🛡 Проверка владельца КАЖДОГО объекта на сервере, неперечислимые id (UUID), тесты матрицы прав, 403 вместо 404-различий.
- ✅ Нарисовать матрицу «роль × объект» своего сайта.

### D2. Misconfiguration: заголовки, debug, .git, бэкапы, права
- 📖 Самый частый реальный класс: `robots.txt` как карта, `.git/` и `.zip` в webroot, debug-режим, права 777.
- 🧪 PlanBox (robots/backup/dev) — полный цикл; `lab-coach scan` до и после «исправлений» (исправляешь копию стенда? нет — фиксируешь в notes, что исправил бы).
- 🛡 CSP/HSTS/X-Frame-Options, выкл debug, нет секретов в webroot, права 644/755, бэкапы вне хостинга.
- ✅ Пройти свой сайт по MAP-TO-MY-SITE строка за строкой (руками из админки).

### D3. Уязвимые компоненты (CVE)
- 📖 Версия → публичная дыра → fix-релиз. Цепочка «инвентарь → обновление → проверка».
- 🧪 Nuclei по PlanBox/Metasploitable → `explain`; сверка версий CMS своего сайта из админки.
- 🛡 Инвентарь версий (ядро/тема/плагины/PHP), обновления с бэкапом, подписка на бюллетени CMS.
- ✅ Назвать 5 версий своего стека по памяти и где смотреть свежие.

## Блок E. Сеть, стойкость, финал

### E1. Слабые сетевые сервисы и privesc-мис конфиги (теория защиты)
- 📖 SSH по паролю, SMB/FTP-аноним, `sudo NOPASSWD`, SUID, writable cron — как их ВИДЕТЬ у себя.
- 🧪 PlanBox шаги 4–5 (своя VM — можно); чужое — никогда.
- 🛡 SSH только по ключу, лишние сервисы выкл, `sudo -l` ревизия на своём VPS, обновления.
- ✅ Вывод `sudo -l` и `ss -tlnp` своего VPS с объяснением каждой строки.

### E2. Логирование, мониторинг, DoS-стойкость (только защита)
- 📖 Атаки этого блока НЕ отрабатываем даже дома (шум/вред), только строим защиту.
- 🛡 Логи входов/ошибок, fail2ban, алерты, rate limit на формах/логине, CDN/кэш перед сайтом, бэкапы с проверкой восстановления.
- ✅ Показать: бан после N неверных входов, письмо-алерт, свежий бэкап с датой.

### E3. Выпускной: комплексный разбор
- Прогнать PlanBox целиком по plan.txt 0–6, собрать `scan-N.json` → `explain`, заполнить notes по шаблону.
- Пройти MAP-TO-MY-SITE по своему сайту, зафиксировать 5 внедрённых защит.
- Привезти сюда: JSON отчёта + список «что закрыл на своём сайте» — разберём вместе.
